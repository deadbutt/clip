# 直播工作台与实时字幕计划

## 目标

把 B 站、Twitch 等直播源接入工作台，支持观看、录制、实时字幕和录制后高质量转录四种组合。

## 阶段

1. **直播工作台基础**：导航入口、频道列表、添加链接、流状态、观看地址、开始/停止录制。
2. **录制入媒体库**：录制文件保存到 `videos/live/`，自动生成媒体记录和封面；录制中断可恢复、结束可进入现有任务流程。
3. **实时 Whisper**：按 6 秒音频窗口、2 秒重叠增量识别，末尾 1 秒延后确认，只发布确认的词，保存实时字幕草稿。
4. **Index-Translate-2B**：通过 `HF_ENDPOINT=https://hf-mirror.com` 下载 GGUF，接入本地 llama.cpp；实时翻译只处理已确认字幕，避免队列无限增长。
5. **直播后处理**：录制完成后可一键创建现有高质量转录任务，重新做说话人标记、校对、切片和 B 站投稿。
6. **稳定性**：断流重连、字幕延迟指标、GPU/队列占用提示、异常诊断和清理策略。

## 设计约束

- 原始直播录制只保存一份；实时字幕是草稿，不能覆盖原视频。
- 观看、录制、实时转录、录制后处理都是独立开关。
- B 站与 Twitch 使用统一的直播会话模型，平台只负责解析流地址。
- Index 2B 先作为可选翻译引擎，不替换现有 HY-MT2，实测后再决定默认值。
- Twitch 的访问令牌、广告和低延迟策略由流解析器处理，不能假设 BiliLiveGo 的旧接口长期可用。

## 实时翻译验证（2026-10-16）

- 用 `runs/11a0ae8d36ff` 的真实媒体 120–132 秒，通过 FFmpeg → 16k PCM → Whisper large-v3-turbo → Index Q4 跑通。
- 输出 3 段双语字幕，未跳过窗口或翻译；后台处理完成耗时 10.362 秒。此为本地文件短片段验证，不等于平台网络延迟或长期直播稳定性验证。
- 实测发现 Index 偶尔复述背景，已改提示词，并在检出背景标记或异常长度时改用单段重译。
- 这份草稿有 Whisper 截断短句、口语歧义等问题，不替代录后高质量转录。实时模式不执行离线的多位置语言探测、缺口补漏、Demucs 或说话人标记。
- 首版同时允许一个实时字幕频道；识别复用现有 Whisper 的锁，离线任务占用模型时会等待。停止后释放本服务启动的 Index 进程；不同会话草稿分别保存在 `videos/live/subtitles/<频道>/<会话>/`，不写根目录 tmp 文件。

“支持平台”表示已接入 BiliLiveGo/Streamlink 的解析入口；不同平台仍受登录态、地区限制和上游接口变化影响，必须在实际链接上逐个平台验证后才能标为可用。
